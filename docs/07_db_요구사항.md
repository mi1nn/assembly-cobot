# 7. DB 요구사항

> 상위 문서: 2. 시스템 요구서
> 

본 시스템은 작업 지시부터 로봇 작업 실행 및 결과 관리까지의 공정 데이터를 통합 관리하기 위한 데이터베이스를 구축한다.

데이터베이스는 다음 정보를 관리할 수 있어야 한다.

- 작업 지시(Work Order)
- Project / Site / Installation Target
- Operation 및 작업 순서
- 작업 Parameter 및 치수
- 구성 부품(Component) 및 수량, 자재 위치/조립 위치 정보
- Robot / Sensor 정보
- Tool / TCP / Fixture / Position / Coordinate System (작업 파라미터로 관리)
- 작업 실행 및 상태
- 작업 이벤트 및 오류
- Force/Torque 센서 데이터
- 작업 결과 및 이력

> **2026-08 구현 현황**: 본 문서가 전제하는 관계형 DB는 `web_app`에서 PostgreSQL + SQLAlchemy(Flask-SQLAlchemy)로 구현이 완료되었다(`web_app/database/schema.sql`, `web_app/app/models/`).

## 7.1 작업 지시 데이터

| ID | 데이터 | 요구사항 |
| --- | --- | --- |
| DB-FR-01 | Work Order | 시스템은 Work Order의 생성, 조회, 수정 및 상태 관리를 지원해야 한다. |
| DB-FR-02 | Project | Work Order와 Project 정보를 연결하여 관리할 수 있어야 한다.
(구현: 별도 `project` 테이블이 아니라 `installation` 테이블의 `project_code`/`project_name` 컬럼으로 관리) |
| DB-FR-03 | Site | Work Order와 작업 현장(Site) 정보를 연결하여 관리할 수 있어야 한다.
(구현: 별도 `site` 테이블이 아니라 `installation` 테이블의 `site_name`/`site_address`/`contact_person` 컬럼으로 관리) |
| DB-FR-04 | Installation Target | Work Order의 설치 대상을 식별하고 관리할 수 있어야 한다. (구현: `installation` 테이블, `work_order.installation_id`로 연결) |
| DB-FR-05 | Priority | Work Order의 우선순위를 저장하고 관리할 수 있어야 한다. |
| DB-FR-06 | Work Order Status | 생성, 대기, 실행, 완료, 실패 등의 작업 상태를 관리할 수 있어야 한다. |
| DB-FR-07 | Installation Target 기준 Work Order | Work Order는 Installation Target을 기준으로 생성되고, 해당 설치 대상을 식별할 수 있어야 한다. |

## 7.2 작업 기준 데이터

| ID | 데이터 | 요구사항 |
| --- | --- | --- |
| DB-FR-08 | Installation Target 사양 | 설치 대상 제품 또는 구조물의 정보를 관리할 수 있어야 한다. |
| DB-FR-09 | Operation 등록 | Installation Target별로 작업 단계 집합(Operation)을 등록하고 관리할 수 있어야 한다. |
| DB-FR-10 | Operation | Installation Target을 구성하는 개별 작업 단계를 관리할 수 있어야 한다. |
| DB-FR-11 | Operation Sequence | Operation의 실행 순서를 관리할 수 있어야 한다. |
| DB-FR-12 | Operation Parameter | 각 Operation에 필요한 작업 조건 및 Parameter를 관리할 수 있어야 한다. |
| DB-FR-13 | Assembly Dimension | 기둥 높이, 설치 간격 등 조립에 필요한 치수를 관리할 수 있어야 한다. |
| DB-FR-14 | Component | Operation에 필요한 구성 부품과 수량을 관리할 수 있어야 한다. (구현: 별도 테이블이 아니라 `operation.components` JSONB 배열로 관리) |
| DB-FR-15 | Component Position | 부품/자재의 현재 위치(픽업 위치)와 조립 위치를 관리할 수 있어야 한다. (구현: `operation.parameter`/`operation.components` JSONB 내부 필드로 관리) |

## **7.3 로봇 작업 데이터**

| ID | 데이터 | 요구사항 |
| --- | --- | --- |
| DB-FR-16 | Robot | 작업에 사용되는 로봇 정보를 관리할 수 있어야 한다. |
| DB-FR-17 | Tool / Gripper | 작업에 사용되는 Tool 및 Gripper 정보를 관리할 수 있어야 한다. |
| DB-FR-18 | TCP | 작업에 사용되는 TCP 정보를 관리할 수 있어야 한다. |
| DB-FR-19 | Fixture | 작업 대상 및 부품의 고정 위치 정보를 관리할 수 있어야 한다. |
| DB-FR-20 | Position | Pick, Place, Insertion 등 작업에 필요한 위치 정보를 관리할 수 있어야 한다. |
| DB-FR-21 | Coordinate System | 작업에 사용되는 기준 좌표계 정보를 관리할 수 있어야 한다. |

DB-FR-17 ~ DB-FR-21은 `operation.parameter` (JSONB)로 관리한다.

## 7.4 작업 실행 데이터

| ID | 데이터 | 요구사항 |
| --- | --- | --- |
| DB-FR-22 | Work Execution | Work Order의 실제 작업 실행 정보를 생성하고 관리할 수 있어야 한다. |
| DB-FR-23 | Operation Execution | 개별 Operation의 실행 이력을 관리할 수 있어야 한다. |
| DB-FR-24 | Execution Status | 작업 실행 상태를 관리할 수 있어야 한다. |
| DB-FR-25 | Execution Start/End Time | 작업 실행 시작 및 종료 시간을 기록할 수 있어야 한다. |

| DB-FR-27 | Retry Count | 작업 재시도 횟수를 기록할 수 있어야 한다. |

## 7.6 **Force/Torque 센서 데이터**

| ID | 데이터 | 요구사항 |
| --- | --- | --- |
| DB-FR-33 | Sensor | 사용 센서의 식별 정보를 관리할 수 있어야 한다. |
| DB-FR-34 | Force/Torque Data | 작업 중 측정된 힘/토크 데이터를 저장할 수 있어야 한다. |
| DB-FR-35 | Sensor Timestamp | 센서 데이터의 측정 시간을 기록할 수 있어야 한다. |
| DB-FR-36 | Execution Link | 센서 데이터를 해당 Operation Execution과 연결할 수 있어야 한다. |
| DB-FR-37 | Sensor Result | 측정 데이터에 대한 작업 결과 또는 판정 정보를 관리할 수 있어야 한다. (⚠ `sensor_data` 테이블에 판정 결과 컬럼 없음 — `data` JSONB 원시 데이터만 저장) |

> **2026-08 구현 현황**: `sensor`, `sensor_data` 테이블은 `web_app/app/models/sensor_data.py`로 매핑되었고, `GET /api/v1/sensor-data`로 Operation Execution 기준 센서 데이터를 조회할 수 있다.
>
> ⚠ 다만 **센서 데이터를 기록하는 경로는 아직 없다**. Controller에 F/T 센서 publish 코드가 없고(IF-23 미구현), Backend에도 쓰기 엔드포인트가 없어 조회 API만 존재한다. 따라서 DB-FR-34~37은 스키마·조회 수준까지만 충족된 상태다.

## 7.7 데이터 이력 및 추적성

| ID | 요구사항 |
| --- | --- |
| DB-FR-38 | 시스템은 각 Operation의 실행 이력을 Work Order와 연결하여 조회할 수 있어야 한다. |
| DB-FR-39 | 시스템은 작업 결과와 발생한 이벤트 및 오류를 해당 Execution과 연결할 수 있어야 한다. |
| DB-FR-40 | 시스템은 측정 결과 및 센서 데이터를 해당 작업 실행과 연결하여 조회할 수 있어야 한다. |
| DB-FR-41 | 시스템은 완료된 작업의 주요 이력을 조회할 수 있어야 한다. |
