# 시스템 구성도 및 작업 순서

## 1. 시스템 아키텍처

```
┌─────────────────────┐
│  Frontend (React)    │  현장 작업자용 웹 대시보드
└──────────┬───────────┘
           │ HTTP / REST (+ WebSocket)
           ▼
┌─────────────────────────────────────┐
│  FastAPI Backend                     │
│  ┌─────────────┐   ┌──────────────┐ │
│  │  REST API    │   │  rclpy Node  │ │  ← 단일 프로세스 내 통합
│  │ (Work Order  │   │ (ROS2 Bridge)│ │
│  │  CRUD 등)    │   │              │ │
│  └──────┬───────┘   └──────┬───────┘ │
└─────────┼──────────────────┼─────────┘
          │                  │
          ▼                  │ ROS2 Topic / Action
┌─────────────────┐          ▼
│  PostgreSQL      │   ┌──────────────────┐
│  (Local install) │   │  ROS2 Node 계층    │
└──────────────────┘   │  - mes_bridge     │
                        │  - dashboard_bridge│
                        │  - process_manager │
                        │    (FSM 기반)      │
                        └─────────┬─────────┘
                                  ▼
                        ┌──────────────────┐
                        │  Doosan M0609     │
                        │  + Gripper        │
                        │  + F/T Sensor     │
                        └──────────────────┘
```

## 2. 기술 스택

| 구분 | 기술 |
|---|---|
| Frontend | React (웹 기반 작업자 대시보드) |
| Backend | Python / FastAPI |
| DB | PostgreSQL (로컬 설치, 데모 안정성 우선) |
| Backend ↔ ROS2 | rclpy 직접 통합 (동일 프로세스 내 브릿징) |
| ROS2 | ROS2 Jazzy, rclpy |
| 로봇 플랫폼 | Doosan M0609, DART Platform / DART Studio |
| 개발 환경 | Ubuntu 24.04, Linux |
| 실시간 통신 | WebSocket (F/T 센서 값, FSM 상태 등 실시간 반영) |

> **설계 원칙**: FastAPI가 REST API 서버와 rclpy 노드 역할을 한 프로세스 안에서 겸함으로써, 별도의 ROS2 Bridge 프로세스와 HTTP 통신을 주고받는 구조보다 지연과 상태 동기화 복잡도를 줄인다. 4인 팀·데모 규모 프로젝트 특성상 프로세스 분리보다 구현·유지보수 부담 최소화를 우선한다.

## 3. ROS2 노드 구성

| 노드명 | 역할 |
|---|---|
| `mes_bridge` | DB(생산 주문/실행 기록)와 ROS2 시스템 간 데이터 연동 |
| `dashboard_bridge` | 프론트엔드 대시보드로 실시간 상태·센서 데이터 전달 |
| `process_manager` | FSM 기반 전체 작업 공정 상태 관리 및 제어 |

## 4. 데이터베이스 핵심 테이블

- `production_orders`, `production_records` (재사용 가능한 2테이블 MES 스키마)
- `work_order` → `work_execution` → `operation_execution` (작업 지시-실행 3단계 계층)
- `force_torque_data` (F/T 센서 원시값, `operation_execution` 단위로 기록)
- `work_event` / `error_log` (진행 로그 및 에러 이력 — 통합 여부 검토 중)
- `robot`, `sensor`, `component`, `installation_target`, `site`, `project` (마스터 데이터)

## 5. 작업 순서 (설치 공정)

1. **포스트(Post) 설치** — 픽앤플레이스로 지그에 삽입
2. **프레임(Frame) 조립** — 포스트 위 프레임 결합
3. **락핀(Lock Pin) 삽입** — 2단계 힘 제어 삽입 (F/T 센서로 삽입 완료 판정)
4. **좌표계 측정** — User Frame 기준 위치 보정
5. **솔라 패널 목업 설치** — 패널 안착 후 F/T 센서로 접촉 확인

> **알려진 한계**: 패널 설치 완료 후 그리퍼 릴리즈 시점의 패널 고정 여부는 F/T 센서만으로 확인이 불가능하며, 이는 최종 발표에서 명시적으로 고지할 예정이다.

## 6. 개발 단계 (Step-by-Step)

```
Step 1. 개발 환경 구성 (Ubuntu 24.04, ROS2 Jazzy, Python)
   ↓
Step 2. PostgreSQL 구축 (로컬 설치)
   ↓
Step 3. FastAPI 기본 서버 구축
   ↓
Step 4. FastAPI ↔ PostgreSQL 연결
   ↓
Step 5. Work Order CRUD API 구현
   ↓
Step 6. FastAPI 내 rclpy 노드 통합 (ROS2 Bridge)
   ↓
Step 7. process_manager (FSM) 구현 및 로봇 제어 연동
   ↓
Step 8. React 대시보드 구현 (실시간 WebSocket 연동)
   ↓
Step 9. F/T 센서 기반 작업 검증 로직 통합 테스트
   ↓
Step 10. 전체 시연 리허설 및 문서화
```

## 7. 팀 구성 및 역할 분담 (검토 중)

| 역할 | 담당 영역 |
|---|---|
| 하드웨어/기구 | 지그, 픽스처 설계 및 조립 |
| 기본 픽앤플레이스 | 포스트/프레임 이송 및 배치 |
| 힘 제어 핀 삽입 | 락핀 2단계 삽입 로직 (F/T 제어) |
| 좌표계 측정 + 패널 설치 | User Frame 보정, 패널 안착 |
